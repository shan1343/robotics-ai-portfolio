# Interfaces for observed or demonstrated workflows
No UI implementation is supplied here. These are interfaces, not working eTL/NotebookLM replay code. Discover an existing validated implementation and verify prerequisites before claiming replay capability.

## First useful execution
A missing recording does not prohibit an authorized one-off task. If native provider tools cannot do it and a browser/Computer Use tool is actually callable, inspect the real target and proceed through observed controls with bounded verification. Never invent selectors, endpoints, exports or cookies. An available browser alone is not proof that login or the requested notebook is accessible.
If the user wants to demonstrate a recurring procedure, use installed Record & Replay after live readiness/consent, pause sensitive steps and keep all raw traces local. The recorder's presence does not mean the course workflow has been recorded. Prefer connectors for any semantic action they already support.

## etl-source-acquisition
Inputs: exact existing course/session and official item, needed source/version, established canonical destination, allowed scope.
Verify: real downloaded file, content/course/session identity, provenance and missing scope. Download time is not lecture date. Wrong course, ambiguous version, missing file or permission changes stop that step. No final submission and no recording credentials.

## notebook-session-reconstruction-docs-export
Inputs: exact existing notebook/session, selected source identities, current approved reconstruction prompt/goal, established destination. Reuse a matching export first.
Verify: actual exported Google Doc recovered through Drive, correct source/session coverage, generated content and omissions. A model saying it read all sources is not coverage evidence. Exported Docs are snapshots.
If execution is blocked, report LM_NOT_RUN plus the exact cause; direct-source assistance, when suitable, is labeled DIRECT_SOURCE and cannot satisfy an explicit claim that LM ran. Missing recordings/audio cannot be silently reconstructed.

## Optional submission preflight
Inspect required files, format and official destination only when requested. Final submit/send and submitted status remain protected. This workflow is not implemented by these interfaces.

## Adding a recurring implementation
After real execution/demonstration, use existing Record & Replay/Skill Creator to produce parameterized code and verification of a later comparable authorized task. Keep generic procedure and tests, never raw profiles/traces/private course content. Add a reference here only after checking the implementation actually exists and its scope works; no imagined automation. Only an executed and independently verified workflow may be marked validated.
