# Source coverage and ordinary Chat handoff

Read this for a whole-lecture review, multi-file exam setup, an uncertain source match, or a cross-surface study restart. A self-contained question does not require a corpus audit.

## Establish the requested scope
For a request to cover all lectures, assignments or notes, inventory the relevant existing provider folders before declaring setup complete. Follow provider pagination or result limits. Compare the requested range against the actual file IDs, not the first search results or a list of selected topics. Record unmatched items and additions outside the requested scope separately. A search miss remains UNKNOWN.

Keep the inventory in the existing Notion course/session section. Include, when available:
- Lecture/session number and date; role of each source (official slides, notes, LM export, textbook, assignment).
- Exact provider URL/file ID, source version or modified time, and the folder used for reconciliation.
- Expected and found units, duplicate-name candidates, unresolved associations and inaccessible material.
- Assignment problem and subpart identifiers from the actual specification; textbook sections and whether page numbers are printed or viewer pages.

Same-name files in different folders can be different objects. Resolve using file ID, folder, session date and body identity. Do not discard a GoodNotes export because it shares a filename with the official slides. Do not infer missing notes from an LM template warning alone: inspect available body/source evidence. Record a user's correction with its provenance; user-confirmed inclusion is distinct from independently verified full fidelity. Reuse a matching existing export rather than automatically rerunning LM.

## Keep connection, reading and learning separate
These are separate claims, not automatic progress steps:
- LINK_VERIFIED: the exact objects are identified and the scoped inventory is reconciled. This does not certify their contents or the receiving Chat's access.
- CONTENT_VERIFIED: the stated source units have actually been read/inspected with a stated method. A successful fetch, title, snippet, summary or file count alone does not qualify.
- STUDIED: actual learner evidence exists under the operating contract. AI reading or generating a solution does not establish it.

Record text/OCR access separately from visual inspection. Preserve unresolved diagrams, handwriting, equations, tables and oral-transcript coverage as specific gaps. Do not claim 100% recovery when the available method cannot support it. A warning can be wrong while full-source fidelity is still unverified.

## Recover the full current study unit
Use exact pointers from the latest course page. For a whole-lecture review, read the current lecture's complete matching LM body, including examples, annotations/transcripts and unresolved questions where present, and inspect the relevant official slides and notes. A topic list is navigation, not an exhaustive syllabus or permission to skip unlisted material. Build the actual teaching coverage from the source sections/pages, including details absent from the handoff summary.

Fit retrieval to the current unit: a full-course setup establishes the whole inventory, while study advances lecture by lecture or problem by problem. Do not load every file on every turn or reread unchanged verified material without reason. If a source is too large or a response is truncated, continue in bounded sections and record the unread remainder; do not silently convert partial access into whole-file coverage.

Keep a short coverage record at meaningful boundaries: source ID/version, requested units, actually inspected sections/pages and method, unresolved source gaps, learner-tested units, next unit. Problem solving must retain all requested subparts. Prioritization for an urgent exam can change order; any deferred coverage remains visible.

## Make a handoff usable in ordinary Chat
The producing surface owns the verified inventory and precise checkpoint; the receiving surface owns fresh retrieval and the teaching it actually performs. Persist the source pointers, scope and remaining units in the existing course/session section. A few suggested topics or links alone are insufficient for a whole-course setup.

At restart, the receiver reads that section and fetches the exact current-unit sources. It does not rediscover filenames unless pointers are stale or missing. Check its actual callable connectors; Work plugin installation does not establish ordinary Chat plugin availability. No automatic branch dispatch, reverse merge, hot reload or background work is implied.

Report inventory verification, actual source inspection and receiver acceptance separately. Receiver acceptance requires an observed supported session recovering the checkpoint and source content; if that was not exercised, label it untested. If the receiving surface cannot access a source, state the exact access gap and continue only within verified accessible material. Do not assert successful synchronization or silently narrow the requested scope.
