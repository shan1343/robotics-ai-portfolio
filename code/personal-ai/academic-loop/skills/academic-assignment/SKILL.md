# Academic assignment
For a whole problem set or multi-file continuation, read [source coverage](../../references/source-coverage.md). Enumerate every requested problem/subpart from the actual specification and keep deferred or unread parts explicit.

Read [the operating contract](../../references/operating-contract.md). For continuation, learning writeback or material portfolio evidence, read [learning and continuity](../../references/learning-and-continuity.md). For an authorized UI preflight, consult [recorded workflow interfaces](../../references/recorded-workflows.md).

1. Recover the exact assignment and last verified checkpoint from Project/current Notion Task and official source via existing providers. Read the actual current specification and rubric: inputs, outputs, submission format, environment, allowed tools, deadline and AI-use rules. Identify conflicts or omissions; do not derive requirements from notification titles or generated summaries.
2. Separate the student's learning/derivation/design/solution reasoning from AI support. Respect the user's requested level of assistance and the verified course rules. Obtain the student's attempt when their solution work is the objective; do not fabricate an attempt, lab data or AI-use disclosure. Directly authorized permissible implementation can use Codex while reasoning practice remains explicit.
3. Use existing calculation/code/artifact capabilities only where useful: check equations/units, execute representative code cases, debug the real error, and create genuine editable DOCX/XLSX/PPTX/IPYNB or other requested files. Load their installed skills before use. Do not replace a requested file with a prose plan or create a new framework/API subscription.
4. Check the artifact against source and rubric: content coverage, calculations/tests, real file readability, formatting/rendering where meaningful, and exact output destination. Inspect generated output, not merely the generator's success message. Re-fetch cloud artifacts and preserve the existing original unless replacement is requested.
5. Update only authorized actual preparation/progress in the existing Task; verify readback. Keep upload/packaging readiness separate from submitted status. Optional submission preflight can inspect filename, format and destination through a validated workflow; final submit/send remains user-controlled.

## Completion

Deliver the requested editable artifact or the bounded tutoring/debugging result with actual checks, limitations and next user-core action. Never auto-submit, mark SUBMITTED from a local file, or mark the user STUDIED because AI finished an artifact.
