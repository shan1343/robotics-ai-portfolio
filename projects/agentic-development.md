# AI 코딩 도구를 쓰는 개발: 실행 범위와 완료 근거를 설계하다

[첫 화면](../README.md) · [Personal AI 사례](personal-ai.md) · [CLI·Skill 근거 안내](../code/personal-ai/CLI_AND_SKILLS_EVIDENCE.md)

**범위: 2026년 9–10월, 개인 Personal AI 개발 실험.** 저는 사용자 목표를 작업 계약으로 바꾸고, Codex CLI·에이전트가 바꿀 파일과 멈출 조건을 정하며, 결과를 테스트와 원본 상태로 확인하는 과정을 배웠습니다. 구현·수정의 상당 부분은 AI 작업자가 수행했습니다. 이 기록은 제가 모든 코드를 단독 작성했다거나 무인 운영 시스템을 완성했다는 주장이 아닙니다.

## 문제: `PASS`가 실제 완료를 뜻하는가

AI 작업자는 그럴듯한 코드와 완료 보고를 빠르게 낼 수 있습니다. 그러나 테스트가 합성 입력만 읽었거나, 저장소의 옛 revision을 검증했거나, GitHub의 실제 결과가 달라졌다면 완료라고 할 수 없습니다. 그래서 작업을 시작할 때 **목표, 입력 출처, 수정 허용 범위, 금지할 부작용, 확인할 실제 결과**를 함께 적었습니다. 예컨대 한 업무 실험에서는 공식 마감일만 기존 Task에 반영하고 실행 시각·우선순위·상태·완료 여부·메모는 보존하도록 범위를 좁혔습니다. 당시 기록은 해당 범위의 provider 재조회와 중복 생성 0건을 보고하지만, 반복 운영의 성공률이나 절약 시간까지 입증하지 않습니다. 출처: 비공개 원본 `04_PORTFOLIO_EVIDENCE_BANK.md`(원본 경로 `development_evidence/archive_mining_20260919/04_PORTFOLIO_EVIDENCE_BANK.md`, PEB-009·010), 공개 해설 [Personal AI 사례](personal-ai.md).

## 제가 구성한 실행 절차

1. **목표와 권한을 분리했습니다.** 작업자가 볼 수 있는 외부 문서·Issue·도구 출력은 자료로 취급하고, 그 안의 지시가 수정 권한을 늘리지 못하게 했습니다. 변경 대상 파일과 금지 대상, 예상 결과, 중단 조건을 먼저 정했습니다.
2. **CLI 작업을 격리했습니다.** Codex 작업에는 저장소 진입점, 필요한 문맥만 읽는 순서, 한정된 브랜치·worktree 범위, 테스트 명령과 결과 영수증을 붙였습니다. 병렬 에이전트나 긴 Goal도 독립된 일이 있을 때만 사용했습니다. 원본 `AGENTS.md`(2026-09-20 무렵 보존본)와 `PAIOS_OPERATIONAL_COMPOUNDING_20260927.md`의 작업·검토 기록이 이를 설명합니다. 이는 모든 개발을 자동으로 수행했다는 뜻이 아닙니다.
3. **완료를 다시 판정했습니다.** 작업자 문구와 CI 배지를 분리하고, 현재 HEAD와 시험 대상 SHA, 테스트 출력, provider 재조회, 변경 파일을 대조했습니다. 누락·충돌·접근 불가 상태는 `BLOCKED` 또는 `UNKNOWN`으로 남겼습니다. 2026-09-27 작업 기록에는 독립 검토가 처음 실패 판정을 낸 뒤 오류를 고치고 재검증한 과정도 보존돼 있습니다. 원본 `PAIOS_OPERATIONAL_COMPOUNDING_20260927.md`.

실제 공개 가능한 판정 로직은 [JavaScript `evaluateCanaryEvidence`](../code/personal-ai/src/lived-canary-evidence.js)에 있습니다. 합성 fixture의 `PASS` 문구를 그대로 통과시키지 않고, 필수 assertion과 부작용 지표를 재계산합니다. [7개 합성 회귀 검사](../scripts/check-evidence.mjs)는 `providerCalls: 0`이므로 이 코드의 입력 계약을 검증할 뿐, GitHub·Gmail 실사용 완료의 증거는 아닙니다.

도구별 역할도 구분했습니다. **Codex CLI**는 저장소 안에서 범위를 정한 실행·수정에, **스크립트**는 동일 입력을 다시 검사하는 데 사용했습니다. **Skill**은 반복될 절차의 발견·전달 형식이고, **플러그인**은 기능을 노출하는 설치 단위이며, **MCP**는 외부 도구·원본 서비스에 닿는 통로입니다. 어느 하나가 설정에 보인다고 나머지의 인증·작동·성과까지 입증되지는 않습니다. 원본 서비스에 쓰는 작업은 실행 영수증뿐 아니라 해당 서비스에서 읽어 온 결과가 필요합니다. Claude Code CLI는 설치·인증 확인 단계로만 표시합니다. 출처: `AGENTS.md`, `.codex/config.toml` 보존본 및 사용자 제공 2026-10-10 환경 확인.

## 실제 코드: Issue 작업 지시와 저장소 접근 범위를 해석하기

승인한 GitHub Issue를 Codex 작업으로 전달하려는 로컬 Runner를 만들면서, 중요한 것은 `프롬프트 전달`보다 **다른 저장소나 외부 작업까지 허용하지 않는 범위 검사**였습니다.

비공개 구현 파일에서 부작용이 없는 함수 다섯 개를 실제 코드로 공개했습니다. [PowerShell 소스](../code/personal-ai/examples/verified-cli-helpers.ps1)는 작업 지시의 `TASK`, `DONE_WHEN`, `TARGET_REPO`를 읽는 파서, 허용한 저장소만 로컬 경로로 매핑하는 함수, Windows PowerShell에서 외부 명령의 종료 코드를 검증하는 함수입니다.

[8개 로컬 테스트](../code/personal-ai/examples/test-verified-cli-helpers.ps1)는 허용되지 않은 저장소를 거부하는지, 예제 Task를 정확하게 구분하는지, 외부 명령의 종료 코드를 검사하는지 확인합니다. 원본 API 호출·GitHub 쓰기·계정 변경 없이 재현할 수 있습니다.

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\code\personal-ai\examples	est-verified-cli-helpers.ps1
~~~

이 코드는 2026년 당시 Runner의 **일부**로, 무인 운영 시스템 전체를 공개·검증한 것은 아닙니다. 원본에는 AI 코딩 지원이 포함됐고, 저는 작업 범위와 수용 기준을 정하고 통합·사용 평가를 했습니다.

## Skill을 채택하기 전에 한 대조 실험

작업을 `SKILL.md`로 포장하면 재사용이 편해질 수 있지만, 발견 가능성과 실행 성과는 다릅니다. 2026-09-19 Agent Skills canary는 **같은 5개 폐기 가능한 fixture**를 기준으로, 명시적 Markdown 절차를 주는 control과 Skill을 사용하는 treatment를 비교했습니다. 판정 항목은 최신 원본 우선, 필수 근거가 없을 때 `BLOCKED`, 거짓 `DONE` 0, 보호 파일 수정 0이었습니다. 사용자가 제시한 Codex·Antigravity **4개 통제 실행 PASS**는 이 제한된 oracle에 대한 결과입니다. 보존된 2026-09-20 요약본 `portable-skills-and-triggers.md`는 Jules를 포함한 5개 arm을 함께 서술하지만, Jules arm의 독립 상태 원문은 이번 공개 편집에서 확인하지 못했으므로 같은 확정치로 합산하지 않았습니다. 실행 속도 개선도 측정되지 않았습니다.

Skill의 효과는 “절차를 매번 지정하는 수고를 줄일 수 있는가”로 해석했습니다. 실제 업무에서 같은 절차가 반복되는지, baseline과 treatment가 같은 허용 범위와 검증 조건을 지키는지, 비용이 줄었는지를 본 뒤 승격해야 합니다. `SKILL_FORGE_CODEX_INTAKE_20260915.md`는 외부 Skill 제작 도구를 분석한 뒤 기존 규격과 검사 기능을 재사용하고 새 런타임 설치를 보류한 기록입니다.

## 구조를 줄인 결정

초기 설계에는 개인 AI를 위한 라우터·스케줄러·메모리 계층까지 떠올릴 수 있었습니다. 그러나 2026-09-16 `ARCHITECTURE.md` 보존본은 이미 이를 **역사적 설계**로 표시합니다. 지금의 판단은 원본 서비스가 데이터를 보유하고, 작은 문맥이 출처와 승인 경계를 알려 주며, 실행 결과는 원본에서 다시 확인하는 쪽입니다. 2026-09-15 `PORTABLE_STATE_COLD_START_EVALUATION_20260915.md`의 84줄 콜드스타트 캡슐은 맹검 질문에서 출처 선택 5/5, 근거 없는 답 회피 5/5였으나 실제 connector가 없어 현재 상태 읽기·복구는 끝나지 않았습니다. 이는 작은 문맥의 가능성이지 24시간 작동하는 개인 AI의 성능 증명이 아닙니다.

Codex용 제한적 로컬 runner의 **설계**도 남아 있지만, 지속 실행·장애 복구·24×7 운영이 검증된 제품으로 소개하지 않습니다. **Claude Code CLI 2.1.137도 설치 상태를 확인했지만**, 이번에 별도 독립 검수를 실행할 때 OAuth 인증 만료(401)로 실제 결과를 확보하지 못했습니다. 따라서 설치·도구 비교와 **Claude Code로 프로젝트를 끝까지 개발한 검증 성과**를 구분합니다. MCP·플러그인도 설정 파일에 이름이 있다는 이유만으로 설치·연결·성공을 주장하지 않습니다. `config.toml`의 비활성 기업용 플러그인 항목은 특히 사용 실적이 아닙니다.

이 사례가 보여 주는 현재 역량은 도구를 많이 붙이는 일이 아니라, **어떤 결과를 믿을 수 있는지와 언제 멈춰야 하는지**를 코드·테스트·원본 대조로 구체화하는 일입니다. 실제 개발 숙련도와 재사용 효과는 계속 검증 중입니다. 원본 파일별 근거와 확인 한계는 [CLI·Skill 근거 안내](../code/personal-ai/CLI_AND_SKILLS_EVIDENCE.md)에 정리했습니다.
