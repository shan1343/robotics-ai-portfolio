# G1 · 보행 학습과 모션 실행 구조

[첫 화면](../README.md) · [보존된 Flat 실행 설정](../evidence/g1/flat-settings.yaml)

**2026년 3–4월 / 10월 · 실물 조작, Isaac Lab·RSL-RL 실습, 보상 변경·재학습, 팀 모션 구조·통합 작업**

3월에는 지지장치 환경에서 G1을 직접 조작했습니다. 이후 원격 GPU에서 보행 학습을 실행하고, 발을 드는 동작과 자세·행동 변화에 대한 보상을 바꾸며 재학습을 시도했습니다. 10월에는 실물 기체를 다시 확인하고 팀 모션 파이프라인의 입력·출력과 실행·전환·평가 구조를 다루고 있습니다.

## 보행 학습에서 확인한 구성

| 요소 | 실제 자료에서 확인한 내용 |
|---|---|
| 로봇 | 기본 Rough 설정의 `G1_MINIMAL_CFG` |
| 환경 | Rough는 `LocomotionVelocityRoughEnvCfg` 상속, Flat은 평면으로 변경 |
| 관측 | Flat에서 height scanner·policy height scan 제거 |
| 행동 | 보존 Flat 설정의 joint-position action scale 0.5 |
| 실행 | Isaac Lab의 RSL-RL train/play, 설정 변경과 재학습 시도 |

정책의 행동을 기준 자세와 배율에 적용해 목표 관절 위치로 전달하는 형태를 읽었습니다. 전체 관측·행동 차원과 PPO 계수는 해당 run의 완성된 config가 없어 확정하지 않았습니다. 현재 팀 G1 29DoF 모델을 당시 개인 실습의 모델로 소급하지 않습니다.

## Rough · 체공과 페널티 조정

| 항목 | 기본 보존본 | 수정 후보의 값 |
|---|---:|---:|
| `feet_air_time` | 0.25 | 0.75 |
| `dof_torques_l2` | −1.5e−7 | −5.0e−8 |
| `dof_acc_l2` | −1.25e−7 | −5.0e−8 |
| `action_rate_l2` | −0.005 | −0.001 |
| `flat_orientation_l2` | −1.0 | −0.5 |
| `undesired_contacts` | `None` | weight −1.0, threshold 1.0, hip/knee 링크 |

발을 드는 보상의 비중을 높이고 움직임을 억제하는 페널티를 완화하려던 수정입니다. 원본 `rough_env_cfg (2).py`에는 `__post_init__`가 클래스 밖에 있어 그 함수 안의 변경이 초기화에서 적용됐는지 확정할 수 없습니다. 별도 Rewards 클래스에 있는 값과 함수 안의 값을 나누어 읽어야 했습니다. 표는 파일 차이이며 성능 개선율이나 실제 적용 결과표가 아닙니다.

## Flat · 과도하게 발을 드는 움직임 줄이기

Flat 수정본의 주석에는 발을 과하게 드는 움직임을 줄이려는 의도가 있습니다. 체공 보상을 0.75에서 0.2로 낮추고 hip·torso 기본 자세 이탈에 각각 −0.5를 적용했습니다.

```python
# flat_env_cfg (1).py의 짧은 설정 발췌
self.rewards.feet_air_time.weight = 0.2
self.rewards.feet_air_time.params["threshold"] = 0.4
self.rewards.joint_deviation_hip.weight = -0.5
self.rewards.joint_deviation_torso.weight = -0.5
```

`base_height_l2`, target height 0.75 제안은 주석 처리돼 있어 적용값으로 집계하지 않았습니다. Rough에서 체공 보상을 높인 시도와 Flat에서 낮춘 수정을 한 번의 개선 실험으로 합치지 않았습니다.

Flat은 평면 지형으로 바꾸면서 관측과 curriculum도 변경합니다.

```python
self.scene.terrain.terrain_type = "plane"
self.scene.terrain.terrain_generator = None
self.scene.height_scanner = None
self.observations.policy.height_scan = None
self.curriculum.terrain_levels = None
```

재생용 클래스는 50개 환경·간격 2.5를 사용하고 관측 오염, 외부 힘과 밀기 이벤트를 끕니다. 학습 환경과 영상 재생의 조건을 구분해 읽었습니다.

## 4월 3일에 보존된 실행 조건

| 항목 | 설정 |
|---|---|
| 병렬 환경 / seed | 8,192 / 42 |
| 물리 dt / decimation | 0.005초 / 4 |
| 설정상 물리 / 정책 주기 | 200 Hz / 50 Hz |
| joint-position action scale | 0.5 |
| episode 길이 | 20초 |
| 속도 명령 범위 | 전진 0.0–1.0, 좌우 −0.5–0.5, 회전 −1.0–1.0 |

[설정 발췌](../evidence/g1/flat-settings.yaml)는 실행 조건이며 실측 최고 속도·성공 횟수가 아닙니다. 보존된 소스 변형 중 어느 버전이 해당 run에 들어갔는지와 영상·checkpoint의 직접 대응은 확인되지 않았습니다.

MuJoCo로 정책을 옮기는 sim-to-sim은 실패했습니다. 최초 오류 로그가 없어 원인을 확정하지 않았습니다. 관측 차원·관절 순서·기준 자세·quaternion·action scale·PD gain·제어 주기는 이후 맞춰 확인할 항목입니다. 실물 조작 영상과 시뮬레이션 영상은 서로 다른 활동의 자료이며 실물 정책 전이 성공으로 표시하지 않습니다.

## 10월 · 팀 모션 파이프라인과 실물 확인

10월 9일 G1 기체와 지지 구조·현장 장비를 확인하고 실행·연구 매뉴얼을 준비했습니다. 팀 파이프라인에서는 영상의 동작을 G1 관절로 옮겨 학습하고 정책을 내보내는 흐름, 실행 환경에 전달할 관측·관절·행동 설정, 동작 사이 전환과 평가 접점을 다루고 있습니다. 파이프라인 개발·반영에 참여하며 구조와 통합 작업을 맡고 있습니다.

```mermaid
flowchart LR
  A[사람의 동작 영상] --> B[GEM-X 모션 추출]
  B --> C[SOMA 기반 G1 관절 변환]
  C --> D[시뮬레이션 학습]
  D --> E[ONNX·설정·참조 모션]
  E --> F[정책 재생·실행 검토]
  F --> G[동작 전환·평가 준비]
```

팀 저장소에 있는 구조를 설명한 도식입니다. 실물 연속 동작 완료를 나타내지는 않습니다. **초기 파이프라인의 구현은 팀 기여**이며, 제가 맡은 개발·반영 범위를 초기 릴리스 전체의 단독 저작으로 설명하지 않습니다.

| 실제 팀 파일 | 구조·통합에서 다루는 내용 |
|---|---|
| `run_motion_pipeline.py` | extract·retarget·padding·prepare·train·resume의 입출력과 재개 조건 |
| `run_training_queue.py` | 여러 입력의 순차 처리와 checkpoint |
| `package_policies.py` | ONNX·`sim2real.yaml`·참조 CSV를 전달할 bundle |
| `verify_motion.py` | 정책 재생과 reference-only·marker·livestream 비교 |

자료의 관측 순서, 관절 순서, action scale과 제어 주기가 다음 실행환경에서도 일치해야 합니다. 동작 전환에서는 종료·시작 상태, guard, 안정 자세 경유와 실패 시 복구를 검토합니다. 현재의 실물 확인·문서 준비와 앞으로의 실행 성능 평가는 별도로 기록합니다.

초기 릴리스와 인수인계는 2026-10-10에 확인한 팀 `main`의 `9b9ff79ef8bf241bdbfc90050a13c7bdb309b329` 기준입니다. 공개 포트폴리오에는 팀 원본을 복제하지 않았습니다.

## 팀 모션 학습의 입력과 모델 설정

현재 팀 소스의 `tracking_env_cfg.py`와 `rsl_rl_ppo_cfg.py`를 읽으며 정책의 입력과 학습 설정을 확인했습니다. 다음 값은 **현재 팀 모션 추종 설정**이며 3–4월 개인 보행 run의 모델 구조가 아닙니다.

| 구성 | 팀 설정에서 확인한 내용 |
|---|---|
| Actor 관측 | 참조 모션 명령·anchor 방향, 몸체 각속도, 상대 관절 위치·속도, 이전 action |
| Critic 관측 | 정책 입력에 더해 참조 anchor 위치와 학습 환경의 추가 상태·선속도 |
| 행동 | 기본 자세 offset을 사용하는 joint-position action |
| Actor / Critic 은닉층 | 각각 `[512, 256, 128]`, ELU |
| PPO | clip 0.2, entropy 0.005, learning rate 1e−3, adaptive schedule |
| 학습 반복 | epoch 5, mini-batch 4, gamma 0.99, lambda 0.95 |
| 수집·저장 | 환경별 24 step, 최대 30,000 iteration, 500 iteration마다 저장 |
| 물리·정책 주기 | dt 0.005초, decimation 4 |

Actor와 Critic이 같은 정보를 쓰지 않으므로, 학습 중 Critic이 보는 추가 상태를 실제 로봇의 정책 입력으로 요구해서는 안 됩니다. 참조 모션 재생과 정책 rollout도 구분해야 합니다. 기준 자세를 그대로 덮어쓰는 대신, 위치·방향·속도 추종 보상과 관절·토크·행동 변화의 페널티를 통해 동작을 학습하는 구조를 검토했습니다.

관측 순서·정책 파일·참조 모션·관절 변환을 함께 전달하는 이유를 이 설정과 연결해 정리했습니다. 위 표는 소스 설정의 설명이며 새로운 학습이나 실물 성능 시험의 결과가 아닙니다.
